## F1 · 数据同步与多设备（WebDAV/iCloud）

### 功能目标
支持 WebDAV（坚果云/Nextcloud/自建）作为同步通道，实现笔记、复习卡、任务等文本类数据的跨设备同步；冲突可解决、可回滚。

### 涉及文件
- 新增：`src-api/src/services/syncService.ts`、`src-api/src/routes/sync.ts`、`src-api/src/controllers/syncController.ts`
- 修改：`src-api/src/index.ts`（注册路由）、`src-ui/src/views/Settings/index.vue`
- 新增表：`wb_sync_cursor`、`wb_sync_conflict`
- 新增前端：`src-ui/src/api/sync.ts`、`src-ui/src/views/Settings/SyncSection.vue`

### UI 界面设计

**位置**：设置中心 `/settings` 新增「数据同步」分区（`SyncSection.vue`）

**布局**（`kb-stack` 纵向，gap:24px）：

```
┌─────────────────────────────────────────────────┐
│ 数据同步                                    [状态点] │
│ ─────────────────────────────────────────────── │
│                                                   │
│ ┌─ WebDAV 配置 ─────────────────────────────┐    │
│ │ 服务器地址  [https://dav.jianguoyun.com/ ]│    │
│ │ 用户名      [__________________________] │    │
│ │ 密码        [__________________________] │    │
│ │                          [测试连接] [保存]│    │
│ └───────────────────────────────────────────┘    │
│                                                   │
│ ┌─ 同步范围 ─────────────────────────────────┐   │
│ │ ☑ 笔记      ☑ 复习卡   ☑ 任务             │   │
│ │ ☑ 习惯      ☑ 日程     ☐ 思维导图         │   │
│ │ ☐ 附件（体积大，谨慎）                      │   │
│ └───────────────────────────────────────────┘    │
│                                                   │
│ ┌─ 同步状态 ─────────────────────────────────┐   │
│ │ ● 已连接  上次同步：2026-08-14 10:30       │   │
│ │ 已同步：笔记 23 / 复习卡 156 / 任务 8      │   │
│ │                          [立即同步] [自动☐]│   │
│ └───────────────────────────────────────────┘    │
│                                                   │
│ ┌─ 冲突记录 (2) ──────────────────────────────┐  │
│ │ ⚠ 「Java并发笔记」2026-08-14 09:15 冲突     │  │
│ │   [查看] [保留本地] [保留远程] [保留两者]   │  │
│ │ ⚠ 「Redis闪卡#12」2026-08-14 09:20 冲突     │  │
│ │   [查看] [保留本地] [保留远程] [保留两者]   │  │
│ └───────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
```

**交互细节**：
- 连接状态点：绿色=已连接 / 橙色=同步中 / 红色=断开 / 灰色=未配置
- 「测试连接」按钮点击后显示 loading → 成功 toast(绿) / 失败 toast(红) + 错误详情
- 「立即同步」点击后：按钮变 loading → 进度条显示「同步中... 笔记 12/23」→ 完成后 toast
- 「自动」开关：开启后启动时自动同步 + 编辑后防抖 30s 同步
- 冲突记录：有冲突时分区标题角标显示数量(红色)，支持逐条解决
- 同步过程不阻塞主线程，失败有 toast 与重试按钮

**复用类**：`.kb-card` 包裹各分区、`.kb-input` 输入框、`.kb-btn-primary` 主按钮、`.kb-btn` 次按钮、`kb-stack` 布局

### 后端接口设计

```
GET    /api/sync/status          → 同步状态（连接/上次同步/计数）
POST   /api/sync/config          → 保存 WebDAV 配置（加密存储）
POST   /api/sync/test            → 测试连接
POST   /api/sync/now             → 立即同步（返回同步结果）
GET    /api/sync/conflicts       → 冲突列表
POST   /api/sync/conflicts/:id   → 解决冲突（body: { action: 'local'|'remote'|'both' }）
PUT    /api/sync/auto            → 开关自动同步 { enabled: bool }
```

### 数据层设计

```sql
wb_sync_cursor (id, table_name, last_sync_at, user_id)
wb_sync_conflict (id, table_name, entity_id, local_data, remote_data, status, created_at, user_id)
```

### 验收标准
- [ ] 设置中心可配置 WebDAV 地址/用户名/密码/同步范围
- [ ] A 设备新建笔记 → B 设备启动后 30 秒内可见
- [ ] 离线编辑后联网，冲突项以 `.conflict` 后缀保留并在通知中提示
- [ ] 同步过程不阻塞主线程，失败有 toast 与重试

## F2 · 系统级全局快捷键体系

### 功能目标
在应用未聚焦时，通过系统级全局快捷键快速唤起核心动作（收集箱/番茄钟/截图OCR/主窗口显隐）。

### 涉及文件
- 修改：`src-tauri/Cargo.toml`（加 `tauri-plugin-global-shortcut`）、`src-tauri/src/lib.rs`
- 修改：`src-tauri/capabilities/default.json`（加 `global-shortcut:default` 权限）
- 修改：`src-ui/src/store/app-store.ts`（`shortcuts` 字段持久化）、`src-ui/src/App.vue`
- 新增：`src-ui/src/views/Settings/ShortcutsSection.vue`

### UI 界面设计

**位置**：设置中心 `/settings` 新增「快捷键」分区（`ShortcutsSection.vue`）

**布局**：

```
┌─────────────────────────────────────────────────┐
│ 快捷键                                           │
│ ─────────────────────────────────────────────── │
│                                                   │
│  功能                  快捷键            状态     │
│  ──────────────────────────────────────────────  │
│  唤起快速收集箱        [⌥ ⇧ N]          ● 已注册 │
│  启停番茄钟            [⌥ ⇧ P]          ● 已注册 │
│  截图 OCR             [⌥ ⇧ S]          ● 已注册 │
│  显示/隐藏主窗口       [⌥ ⇧ Space]      ● 已注册 │
│                                                   │
│  ──────────────────────────────────────────────  │
│  自定义绑定                                       │
│  点击右侧输入框 → 按下新组合 → 自动检测冲突       │
│                                                   │
│  [恢复默认]                          [应用更改]   │
└─────────────────────────────────────────────────┘
```

**交互细节**：
- 快捷键显示框：`kb-input` 样式，只读，显示当前组合（如 `⌥ ⇧ N`）
- 点击「重新绑定」→ 输入框进入监听态（边框高亮 + 提示「请按下新组合...」）→ 按下组合键自动捕获 → 冲突检测
- 冲突检测：若组合已被系统/其他应用占用，显示红色提示「该组合已被占用，请换一个」
- 状态列：绿色●=已注册 / 红色●=未注册或冲突
- 「恢复默认」一键重置为四组默认快捷键
- 改绑后立即生效无需重启

**默认快捷键**：
- `⌥⇧N` → 唤起快速收集箱（emit `quick-capture:open`）
- `⌥⇧P` → 启停番茄钟
- `⌥⇧S` → 截图 OCR
- `⌥⇧Space` → 显示/隐藏主窗口

### 验收标准
- [ ] 应用未聚焦时按 `⌥⇧N` 直接弹出快速收集框，输入后回车入库
- [ ] 设置中心可改绑，改绑后立即生效无需重启
- [ ] 退出应用后快捷键不再响应

## F4 · 单模块数据导出（MD/PDF/Anki）

### 功能目标
支持核心学习资产的单模块导出，便于迁移到移动端（Anki）、分享（PDF/HTML）、归档（Markdown）。

### 涉及文件
- 修改：`src-api/src/controllers/noteController.ts`、`reviewsController.ts`、`storyController.ts`、`mindmapController.ts`
- 修改：`src-api/src/services/noteService.ts` 等（加 `exportAsMarkdown` / `exportAsApkg`）
- 新增依赖：`genanki-js`（或自写 apkg 生成器）
- 修改前端各列表页工具栏：加「导出」按钮

### UI 界面设计

**模式**：在各模块列表页工具栏新增「导出」下拉按钮

**笔记列表页** `/workbench/notes`：
```
[筛选栏]  ...  [导出▼]
                  ├ 导出为 Markdown
                  ├ 导出为 PDF
                  ├ 导出为 HTML
                  └ 批量导出 (选中 N 篇 → zip)
```

**复习卡列表页** `/workbench/review/card-list`：
```
[筛选栏]  ...  [导出▼]
                  ├ 导出为 Anki (.apkg)
                  ├ 导出为 CSV
                  └ 导出为 Markdown
```

**故事详情页**：
```
[工具栏]  ...  [导出▼]
                  ├ 导出为 HTML（含样式）
                  └ 导出为 Markdown
```

**思维导图页** `/mindmap`：
```
[工具栏]  ...  [导出▼]
                  ├ 导出为 SVG
                  ├ 导出为 PNG
                  ├ 导出为 OPML
                  └ 导出为 Freemind (.mm)
```

**导出进度反馈**：
- 点击导出 → 按钮变 loading → 文件生成 → 浏览器自动下载 → toast「导出成功」
- 批量导出：进度条 `导出中... 3/23`

**交互细节**：
- 导出按钮用 `.kb-btn` + 下拉用 `.kb-dropdown-trigger` / `.kb-dropdown-panel` / `.kb-dropdown-item`
- PDF 导出优先走前端 `window.print()` 方案（复用 `markdown.ts` 渲染）
- 导出文件名含日期：`笔记_2026-08-14.md`

### 后端接口设计

```
GET  /api/notes/:id/export?format=md|pdf|html    → 返回文件流
POST /api/notes/export-batch                      → body: { ids: [], format: 'md' } → zip
GET  /api/reviews/cards/export?format=apkg|csv|md → 文件流
GET  /api/stories/:id/export?format=html|md       → 文件流
GET  /api/mindmaps/:id/export?format=svg|png|opml|mm → 文件流
```

### 验收标准
- [ ] 单篇笔记可导出 .md / PDF，PDF 排版与阅读模式一致
- [ ] 复习卡可导出 .apkg，导入 Anki 后正反面正确
- [ ] 故事导出 HTML 在浏览器打开样式不丢
- [ ] 批量导出生成 zip，文件名含日期

## F5 · AI 流式输出扩展

### 功能目标
把长文本生成类 AI 端点改造为 SSE 流式，降低首字等待，提升交互体验。

### 涉及文件
- 修改：`src-api/src/lib/llm.ts`（`chatStream` 完善）、`src-api/src/controllers/aiController.ts`
- 修改：`src-api/src/routes/ai.ts`
- 修改前端：`src-ui/src/api/ai.ts`、`src-ui/src/api/sse.ts`、各 view 的 AI 按钮调用

### UI 界面设计

**核心交互模式**：流式逐字渲染 + 停止生成按钮

**各场景的流式 UI**：

1. **RAG 问答** `/ai-chat`：
```
┌─────────────────────────────────┐
│ 🧑 Java 的 ConcurrentHashMap     │
│                                   │
│ 🤖 ConcurrentHashMap 是 Java 5   │  ← 逐字渲染，光标闪烁
│    引入的线程安全哈希表▌          │
│                                   │
│              [⏹ 停止生成]         │  ← 流式中显示停止按钮
└─────────────────────────────────┘
```

2. **笔记生成/续写** `/workbench/notes/:id`：
```
┌─ AI 续写 ────────────────────────┐
│ ...正在生成▌                      │  ← 输入区域内逐字插入
│                                   │
│ [采纳] [重新生成] [停止生成]      │
└───────────────────────────────────┘
```

3. **AI 日报文案** `/daily-report`：
```
┌─ 今日学习日报 ────────────────────┐
│ 昨日你完成了 3 篇笔记▌            │  ← 逐字渲染
│ ...                               │
│              [⏹ 停止生成]         │
└───────────────────────────────────┘
```

**交互细节**：
- 流式开始：AI 按钮变 loading → 内容区开始逐字出现（打字机效果）
- 流式中：显示「停止生成」按钮（`kb-btn-sm` + 停止图标），已生成内容保留
- 流式结束：停止按钮消失，显示操作按钮（采纳/重新生成/复制）
- 流式中可点击「停止生成」→ 立即中断，已生成内容保留可用
- 未配置 Key 时走降级 mock，不报错（toast 提示「AI 未配置，使用模拟数据」）
- 首字响应 < 1.5s

**需改造的端点**（按优先级）：
1. `/api/ai/rag/ask` → RAG 问答
2. `/api/ai/note/generate` / `/note/extend` → 笔记生成/续写
3. `/api/ai/story/draft` / `/capture/draft-note` → 草稿生成
4. `/api/ai/insight/report` → AI 日报文案
5. `/api/ai/review/mnemonics` → 助记口诀

**保留一次性返回**：评分类（`/recall/score` / `/story/clarity`）、JSON 结构类（`/tags` / `/flashcards`）

### 验收标准
- [ ] RAG 问答首字响应 < 1.5s，逐字渲染无卡顿
- [ ] 流式过程中可「停止生成」，已生成内容保留
- [ ] 未配置 Key 时仍走降级 mock，不报错
