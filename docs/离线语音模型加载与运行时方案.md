# 离线语音模型加载与运行时方案

> 版本：v1.0（2026-08-13） · 状态：设计评估，未实现
> 关联：《桌面端技术架构与功能手册》§7.24（离线模拟面试/语音通话）

## 0. 结论速览

| 议题 | 结论 |
|---|---|
| 模型不入包、首次按需下载 | ✅ 可行，推荐。安装包稳定 174MB（含 strip） |
| 设置页选模型（tiny/base/small） | ✅ 可行，实现成本低 |
| 运行方式可切（WASM / 原生侧车） | ⚠️ 可行但**两条路径当前都跑不通**，需先修 4 个硬阻塞 |
| whisper-server 二进制是否也走下载 | ❌ **不建议**，改为内置（+5MB）。见 §5.2 签名风险 |

**一句话**：模型走下载是对的；可执行二进制走下载在 macOS arm64 上是坑（Gatekeeper + 强制签名），应内置。

## 2. WASM 路线可行性评估

### 2.1 核心阻塞：worker 调用的 API 不存在

whisper.cpp `examples/whisper.wasm` 通过 embind 只导出三个函数：

```
Module.init(path_model) -> instance_index    // 从 MEMFS 读模型
Module.full_default(index, audio, lang, nthreads, translate) -> 0|错误码
Module.free(index)
```

现有 worker 的三处假设全错：

| 现有代码 | 实际 |
|---|---|
| `w.createWhisper({ model: modelPath })` | 不存在。需 `Module.init('whisper.bin')` |
| 把 URL 当 `model` 传进去 | 无效。**必须自己 fetch 模型字节，再 `Module.FS_createDataFile('/', 'whisper.bin', bytes, true, true, true)` 挂进 MEMFS** |
| `const res = await m.transcribe(...)`，从返回值取 `res.text` | **`full_default` 返回状态码，不返回文本**。识别结果通过 emscripten 的 `print`/`printErr` 回调**逐段异步吐 stdout**，必须劫持 `Module.print` 累积文本，并自行判定「转写结束」 |

→ WASM 路线要通，`whisper.worker.js` 需**基本重写**，而非注释里说的「只改一处」。

### 2.2 其余 WASM 约束

| 约束 | 影响 |
|---|---|
| `whisper.wasm` 官方无预编译下载 | 需本机 emscripten 构建。新版 whisper.cpp 已转 CMake，脚本里的 `emmake make -C examples/whisper.wasm` 可能已失效，需改 `emcmake cmake` |
| 多线程版依赖 `SharedArrayBuffer` | 需侧车对 `/models/*` 与页面响应加 `COOP: same-origin` + `COEP: require-corp`。**加了会连带影响所有同源资源加载**，风险外溢；单线程版免此要求但慢 2~4× |
| 模型需完整驻留 MEMFS + WASM heap | base-q5_1（57MB）峰值内存约 **400~600MB**，与 WebView 其它内存叠加 |
| 模型缓存是模块级单例 | `whisper.worker.js:14` 的 `let model = null` + `ensureModel` 只认第一次的 `modelPath` → **设置页切换模型不生效**（必须销毁 worker 重建） |

### 2.3 WASM 路线结论

**可行但代价高**：需重写 worker + 自建 wasm + 处理 COOP/COEP + 接受 2~4× 速度损失。
**建议定位为「兜底档」**，不作为默认路径。产物 `whisper.wasm`+`whisper.js` 合计仅约 1~2MB，**建议内置进包**（不走下载），这样兜底路径永远可用。

## 3. 架构设计

### 3.1 关键设计：`/models` 双根托管（最小侵入的核心技巧）

生产环境 `getModelsDir()` 指向 `.app/Contents/Resources/models`，**只读**——往里写会破坏代码签名。下载的模型必须落可写目录。

`@fastify/static` 实测版本 **6.12.0**，其 `root` 支持数组并按序查找。因此：

```
src-api/src/index.ts
  root: [ getModelsCacheDir(),   // 可写：<dataDir>/models   ← 下载的模型，优先
          getModelsDir() ]       // 只读：.app Resources/models ← 内置 wasm 等兜底
  prefix: '/models/'
```

**收益**：前端 URL `/models/whisper/xxx.bin` **一个字都不用改**，WASM 与原生侧车共用同一套文件，下载后自动生效。

`getModelsCacheDir()` 新增于 `src-api/src/lib/paths.ts`，实现为 `dataSubDir('models')`，即
`~/Library/Application Support/com.lectoforge.desktop/models/`（已是现成的可写目录解析链）。

### 3.2 下载由侧车执行，不用 Tauri 插件

| 方案 | 取舍 |
|---|---|
| ✅ **Node 侧车下载** | 复用现成可写目录；`Range` 断点续传、SHA256 校验、`.part`→`rename` 原子落盘都在 Node 里最顺；**完全避开 Tauri 远程来源 ACL「三处齐改」的坑**（记忆中已记录的高频踩点）；进度可走已有 SSE 模式 |
| ❌ 前端 fetch + `tauri-plugin-fs` 写盘 | 需改 `capabilities` 加 `remote.urls` + `fs:allow-write`；57MB 数据经 IPC 传给 Rust 再落盘，内存与性能都差 |
| ❌ Rust 端下载 | 需新增 `tauri-plugin-http` + 新 invoke 命令 + 改 `build.rs` + 改 capabilities，改动面最大 |

### 3.3 模型清单（Registry）

硬编码在 `src-api/src/lib/modelRegistry.ts`，字段：

```
{ id, label, file, sizeBytes, sha256, quality, speedHint,
  urls: [ hfMirrorUrl, hfOfficialUrl ] }   // 镜像优先，官方兜底
```

初始三档：`whisper-tiny-q5_1` / `whisper-base-q5_1`（默认）/ `whisper-small-q5_1`。
体积用 §1.3 实测值，前端直接展示「56.9 MB」而非模糊的「约 60MB」。

### 3.4 配置持久化

新增 `<dataDir>/stt-config.json`（**独立文件**，理由同 `pomodoro-config.json`：与 AI 网关配置语义无关、改动频率不同，混进 `ai-config.json` 会互相污染）：

```
{ runtime: 'auto' | 'wasm' | 'native',
  modelId: 'whisper-base-q5_1',
  nativeUrl: 'http://127.0.0.1:8080',
  threads: 4 }
```

`runtime: 'auto'` 语义：探测 `nativeUrl` 健康 → 用 native；否则回退 wasm；两者都不可用 → 明确报错并引导去设置页下载。

### 3.5 端点契约（新增 6 个）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/models/registry` | 返回可选模型清单 + 每个的 `installed` / `downloading` 状态 |
| POST | `/api/models/download` | body `{modelId}`，启动下载（幂等，重复调用返回进行中任务） |
| GET | `/api/models/download/stream` | **SSE** 推进度：`progress{modelId,received,total,pct,speed}` → `done` / `error` |
| POST | `/api/models/cancel` | body `{modelId}`，中断并保留 `.part` 供续传 |
| DELETE | `/api/models/:modelId` | 删除已下载模型，释放磁盘 |
| GET/PUT | `/api/stt/config` | 读写 §3.4 的 stt-config |

> SSE 属信封唯一例外（同 `/api/interview/*`），直接 `reply.raw` 写 `text/event-stream`。

### 3.6 前端改动

- **设置页**：扩展已有卡片「本地模型（离线模拟面试）」(`Settings/index.vue:201`)，新增
  - 运行方式单选：自动 / WASM（慢，免安装）/ 原生侧车（快）
  - 模型列表：每档显示体积 + 中文精度提示 + 「下载 / 删除 / 使用中」按钮 + 下载进度条
  - 磁盘占用汇总 + 一键清理
- **`whisperClient.ts`**：`transcribeAudio` 增加 runtime 分派——native 走 `POST /api/interview/transcribe`（已存在），wasm 走本地 worker。
- **切模型必须销毁 worker**：修 §2.2 的单例缓存 bug，`whisperRuntime.ts` 暴露 `disposeWorker()`，模型变更时调用。

## 4. 优缺点

### 优点

| # | 优点 |
|---|---|
| 1 | 安装包不因语音功能膨胀；**叠加 strip 后反而从 197MB 降到 174MB** |
| 2 | 不用语音的用户零下载负担；用了的人下载一次后永久离线，不违背「离线应用」定位 |
| 3 | 用户按机器性能与精度需求自选档位（30.7 / 56.9 / 181.3 MB） |
| 4 | 双根托管让 URL 不变，WASM 与原生侧车共用模型文件，**不重复占盘** |
| 5 | 下载在侧车侧，零 Tauri ACL 改动，避开项目已知高频踩点 |
| 6 | 双运行时互为兜底，原生不可用时功能不至于完全瘫痪 |

### 缺点

| # | 缺点 | 缓解 |
|---|---|---|
| 1 | 首次使用需联网下载（与「纯离线」宣传有张力） | 文案明确为「一次性下载，之后永久离线」；提供离线手动导入入口（拖入 .bin 文件） |
| 2 | 新增下载器、进度、校验、续传、清理一整套代码 | 约 500~700 行，一次性成本 |
| 3 | 两条运行时 = 两套代码路径，测试矩阵翻倍 | native 为主、wasm 为兜底，wasm 只保基本可用 |
| 4 | 用户可能选了模型却没下载就用 → 需明确态 | 用 `installed` 状态驱动 UI，未装则按钮为「下载并使用」 |
| 5 | HF 在国内不稳 | 镜像优先 + 官方兜底 + 失败可续传 |

## 5. 技术风险清单

### 5.1 高风险

| # | 风险 | 后果 | 对策 |
|---|---|---|---|
| R1 | **往只读 `.app/Resources` 写入** | 破坏代码签名，应用无法启动 | 下载目标必须是 `getModelsCacheDir()`；代码里对 `getModelsDir()` 只读断言 |
| R2 | **WASM worker API 全错**（B4） | 切到 wasm 直接报错，功能不可用 | 按 §2.1 重写 worker；先用官方 index-tmpl.html 对照验证 |
| R3 | **COOP/COEP 外溢** | 为多线程 wasm 加响应头，可能连带打断其它同源资源/图片/iframe 加载 | 优先用**单线程 wasm 构建**，彻底规避；确需多线程时只对 wasm 路由加头并全量回归 |
| R4 | 模型下载中途中断留下半文件 | 下次加载得到损坏模型，报错难定位 | `.part` 临时名 + SHA256 校验通过才 `rename`；校验失败自动删除并重试 |

### 5.2 ⚠️ 为什么 `whisper-server` 二进制**不能**走下载

这是本方案最重要的一条风险判断：

| 环节 | 问题 |
|---|---|
| Gatekeeper 隔离属性 | 下载所得文件被打 `com.apple.quarantine`，直接执行被拦，需 `xattr -d com.apple.quarantine` |
| **arm64 强制签名** | Apple Silicon 上**未签名/签名失效的可执行文件会被内核静默 SIGKILL，无任何报错输出** |
| 修复需 `codesign` | 需 `codesign -s - -f`，依赖 Xcode Command Line Tools，**不能假设用户机器有** |

> 这个坑本项目**已实测踩过**：对 Node 侧车二进制做 `strip -x` 后，`./node --version` 完全无输出、静默被杀，重新 `codesign -s - -f` 后恢复正常。下载来的二进制是同一类问题。

**结论**：`whisper-server`（arm64+Metal，约 **5MB**）**内置进包**，随主构建一起签名/公证。
只有大体积模型（30~181MB）走下载。**用 5MB 换掉整类签名风险，极其划算。**

对应改动：`tauri.conf.json` 的 `bundle.resources` 增加 `whisper-server` 到 `models/`（或独立 `bin/`），
并把 `lib.rs:365` 的 `WHISPER_BIN` 默认路径指向它；`fetch-models.sh` 改为在**构建期**准备该二进制。

### 5.3 中低风险

| # | 风险 | 对策 |
|---|---|---|
| R5 | 切换模型后 native 侧车不生效（`whisper-server -m` 启动时固定） | 切模型需重启侧车进程；`WhisperSidecar` 增加 `restart_with_model()`，或干脆用 `whisper-server` 的多模型参数 |
| R6 | 切换模型后 wasm 仍用旧模型（§2.2 单例 bug） | `disposeWorker()` 后重建 |
| R7 | 端口 8080 被占用 | 启动前探测，占用则顺延（8080→8090）并写回 `stt-config.nativeUrl` |
| R8 | 磁盘空间不足 | 下载前用 `statfs` 检查 ≥ `sizeBytes × 1.2`，不足则拒绝并提示 |
| R9 | 同一模型并发重复下载 | 内存态 `Map<modelId, task>` 加锁，重复请求复用同一任务 |
| R10 | 已下载模型被外部删除 | 每次使用前 `existsSync` + 体积校验，缺失则回落到「未安装」态 |
| R11 | 用户在下载中途关闭应用 | `.part` 保留，下次进设置页显示「可续传」 |

## 9. 离线 TTS（Piper 本地神经网络语音合成，A 阶段，2026-08-13 落地）

> 与本文 whisper STT 同源「离线语音模型」主题，但属独立能力：解决朗读「人机感」。whisper 是「听」，Piper 是「说」。

### 9.1 为什么选 Piper（而非云端 TTS）
- **离线契合**：Piper 是 C++ VITS，中文有 `zh_CN-huayan` / `zh_CN-chaowen` / `zh_CN-xiao_ya` 等很自然的嗓音，全本地、语音不出本机，与 App 离线定位一致。
- **架构轻**：不依赖 Python/Flask，复用现有 Node 侧车 `child_process.spawn` 一次性拉起合成（面试朗读非实时，spawn 足够、省常驻内存），与 whisper 侧车同范式。
- 云端 TTS（OpenAI/Edge/ElevenLabs）质量更高但需联网 + Key，与离线定位冲突，仅作可选。

### 9.2 产物布局与构建（关键坑已踩实）
- 打包产物 `resources/models/piper/`：`piper`（arm64 二进制）+ 3 个 dylib（`libespeak-ng` / `libpiper_phonemize` / `libonnxruntime`，含符号链接）+ `espeak-ng-data/`（约 18MB 音素数据）。`tauri.conf.json` 已把 `../resources/models` 整体映射进 `.app/Contents/Resources/models`，`piper/` 自动随包。
- ⚠️ **官方 `piper_macos_aarch64.tar.gz` 实际是 x86_64 且缺 3 个 dylib**，直接跑会 `dyld incompatible architecture (have arm64, need x86_64)` 退出 134。必须 `git clone --recursive https://github.com/rhasspy/piper.git` 从源码 `cmake -DCMAKE_OSX_ARCHITECTURES=arm64 && make` 全量构建。
- dylib 经 `@executable_path` 解析：`scripts/build-piper.sh` 把官方 build 的绝对 rpath（`/tmp/piper-src/build/{fi,si,pi}/lib`）重写成 `@executable_path` 并 ad-hoc codesign + 去隔离属性。
- espeak-ng 数据经 `ESPEAK_DATA_PATH` 环境变量指明（**cwd 无效**）；`piperTtsService.ts` spawn 时显式注入 `env.ESPEAK_DATA_PATH = <piperDir>/espeak-ng-data`。
- `resources/models/` 已被 `.gitignore` 忽略，Piper 二进制靠 `scripts/build-piper.sh` 在打包前再生，不入库（与 whisper 一致）。

### 9.3 运行时与分发
- Node `services/piperTtsService.ts`：`spawn(piper, ['--model', <onnx>, '--output_raw'])`，stdin 喂文本、stdout 收 raw PCM16 → `encodeWav()` 包成 WAV，经 `POST /api/tts/synthesize` 回传前端 `<audio>` 播放；超时 60s SIGKILL。
- 前端 `lib/tts/ttsDispatch.ts`：每次 `synthesize()` 实时读 `tts-config.json.engine`——`piper` 本地合成 / `browser` 系统 Web Speech（B 阶段快赢）；piper 失败自动回退 browser，`stopSynthesis()` 同时 pause `<audio>` 与 `cancelSpeech()`。

### 9.4 音色注册与下载（沿用 whisper 范式）
- `services/ttsVoices.ts` 注册 4 个中文音色（华岩·标准 63MB / 华岩·极速 / 朝闻·男声 70MB / 小雅·女声 70MB），每个含 `<file>.onnx` + `<file>.onnx.json`（缺一个跑不起来）。
- 仓库实测路径：HF `rhasspy/piper-voices` 下的 `zh/zh_CN/<speaker>/<quality>/`（**无** `voices/` 前缀；**无** zh_CN-chen）。下载源 `hf-mirror.com` 主、`huggingface.co` 兜底。
- 音色不随包内置、首次按需下载到 `<dataDir>/models/piper/`，与 `getModelsDir()` 双根（可写优先、Resources 兜底）一致。

### 9.5 端点（6 个，路由模块 `tts-voices`）
`GET /api/tts-voices`、`GET/POST /api/tts-voices/config`、`POST /api/tts-voices/:id/download`（SSE）、`DELETE /api/tts-voices/:id`、`POST /api/tts/synthesize`（返回 `audio/wav`）。

### 9.6 验证记录
- `piper --help` 冒烟（dylib 可加载）；Node `synthesize()` 实测合成中文 → 有效 WAV（PCM16 单声道 16000Hz，约 3.9s，real-time factor ≈ 0.03）。
- `src-api tsc --noEmit` 与 `src-ui vite build` 均通过。
