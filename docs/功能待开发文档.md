## 2. P1 优先级功能（核心缺口，建议优先排期）

### F1 · 数据同步与多设备

**现状证据**：
- `src-api/src/services/` 全目录无 `syncService` / `webdav` / `cloudSync` 任何同步服务文件。
- `src-tauri/src/lib.rs` 的 `start_backup_scheduler`（行 1567）仅做本地 zip 定时备份，无远程上传。
- 多设备唯一手段是手动导入/导出 zip，无法做到「打开另一台设备自动续上」。

**目标**：支持 WebDAV（坚果云 / Nextcloud / 自建）作为同步通道，实现笔记、复习卡、任务等文本类数据的跨设备同步；冲突可解决、可回滚。

**实现要点**：
1. **同步策略**：以 `updatedAt` 时间戳为基准的 last-write-wins；对结构化表（笔记/复习卡/任务）做行级同步，对文件型数据（思维导图 JSON / 上传附件）做文件级同步。
2. **冲突解决**：检测到 `updatedAt` 双向变更时，保留两者（旧版本加 `.conflict-<ts>` 后缀）并通知用户，不自动合并。
3. **加密**：复用 `src-api/src/lib/vault.ts` 已有的加密能力，同步前对敏感数据加密，WebDAV 服务端只见密文。
4. **增量**：维护 `sync_cursor` 表记录各表最后同步时间戳，避免全量拉取。
5. **触发**：手动同步（设置中心按钮）+ 启动时自动同步 + 编辑后防抖同步。

**涉及文件**：
- 新增：`src-api/src/services/syncService.ts`、`src-api/src/routes/sync.ts`、`src-api/src/controllers/syncController.ts`
- 修改：`src-api/src/index.ts`（注册路由）、`src-ui/src/views/Settings/index.vue`（同步配置区）
- 新增表：`wb_sync_cursor`（记录各表同步游标）、`wb_sync_conflict`（冲突记录）

**验收标准**：
- 设置中心可配置 WebDAV 地址 / 用户名 / 密码 / 同步范围（勾选表）。
- A 设备新建笔记 → B 设备启动后 30 秒内可见。
- 离线编辑后联网，冲突项以 `.conflict` 后缀保留并在通知中提示。
- 同步过程不阻塞主线程，失败有 toast 与重试。

### F2 · 系统级全局快捷键体系

**现状证据**：
- `src-tauri/` 全目录 grep `globalShortcut` → No matches。
- `src-tauri/Cargo.toml` 未引入 `tauri-plugin-global-shortcut` 依赖。
- `src-tauri/src/lib.rs` 的 `invoke_handler`（行 999）注册的 14 个命令中无任何 shortcut 命令。
- 应用内仅有 ⌘K 命令面板，应用失焦后无效。

**目标**：在应用未聚焦时，通过系统级全局快捷键快速唤起核心动作（收集箱 / 番茄钟 / 截图 OCR / 主窗口显隐）。

**实现要点**：
1. 引入 `tauri-plugin-global-shortcut`，在 `lib.rs` setup 阶段注册默认快捷键：
   - `⌥⇧N` → 唤起快速收集箱（`QuickCaptureModal`，emit `quick-capture:open` 事件）
   - `⌥⇧P` → 启停番茄钟（调用 `pomodoroStore.startTimer/pauseTimer`）
   - `⌥⇧S` → 截图 OCR（复用 `captureScreenshot()` + `OcrModal.vue`）
   - `⌥⇧Space` → 显示/隐藏主窗口（`show()/hide()` 切换）
2. 快捷键可在设置中心自定义绑定，持久化到 `app-store.ts` 的 `settings.shortcuts`。
3. 注册冲突检测：用户绑定到已被系统占用的组合时提示。
4. 应用退出时注销全部快捷键（避免僵尸绑定）。

**涉及文件**：
- 修改：`src-tauri/Cargo.toml`（加依赖）、`src-tauri/src/lib.rs`（注册 + 命令 `register_global_shortcut` / `unregister_all`）
- 修改：`src-tauri/capabilities/default.json`（加 `global-shortcut:default` 权限）
- 修改：`src-ui/src/store/app-store.ts`（`shortcuts` 字段持久化）、`src-ui/src/App.vue`（监听 shortcut 事件）
- 新增：`src-ui/src/views/Settings/ShortcutsSection.vue`（快捷键配置区）

**验收标准**：
- 应用未聚焦时按 `⌥⇧N` 直接弹出快速收集框，输入后回车入库。
- 设置中心可改绑，改绑后立即生效无需重启。
- 退出应用后快捷键不再响应。

### F3 · 统一提醒与通知中心

**现状证据**：
- `src-tauri/src/lib.rs` 的 `start_reminder_scheduler`（行 1113）仅轮询 `/api/workbench/reviews/due-count`（行 1129），只弹复习提醒。
- `taskService.ts` / `habitService.ts` / `scheduleService.ts` 均无 due 相关的提醒推送方法被 Rust 侧调用。
- `trigger_notification` 命令目前只被番茄钟调用。

**目标**：把单一「复习提醒」升级为多源统一通知中心，覆盖任务到期 / 习惯打卡 / 日程临近 / 复习到期四类。

**实现要点**：
1. 后端新增聚合端点 `GET /api/notifications/due`：一次返回所有待提醒项（复习计数 + 今日到期任务 + 未打卡习惯 + 未来 N 分钟日程），避免 Rust 侧多次回环。
2. Rust 侧 `start_reminder_scheduler` 改为轮询该聚合端点，按类型合并去重通知（避免一次响 4 个通知）。
3. 用户可在设置中心按类型开关提醒（复习 / 任务 / 习惯 / 日程各自独立开关），持久化到 `app-store.ts`。
4. 通知点击跳转：复习→`/review`、任务→`/tasks?date=today`、习惯→`/habits`、日程→`/calendar`。
5. 勿扰时段：设置「22:00–08:00 不提醒」窗口。

**涉及文件**：
- 新增：`src-api/src/services/notificationService.ts`、`src-api/src/routes/notifications.ts`、`src-api/src/controllers/notificationController.ts`
- 修改：`src-api/src/index.ts`（注册路由）、`src-tauri/src/lib.rs`（`start_reminder_scheduler` 改造 + 通知点击路由）
- 修改：`src-ui/src/store/app-store.ts`（提醒开关 + 勿扰时段持久化）、`src-ui/src/views/Settings/index.vue`

**验收标准**：
- 任务今日到期 → 当天 09:00 弹通知，点击跳任务清单今日视图。
- 习惯未打卡 → 设定时刻（如 21:00）弹提醒。
- 勿扰时段内不弹任何通知，延迟到窗口结束后合并推送。
- 各类型可独立开关。

### F4 · 单模块数据导出（MD / PDF / Anki）

**现状证据**：
- `src-api/src/controllers/` 全目录 grep `export` → 仅 `qaBankController` 的 `importMarkdown` / `importPdf`（都是导入）。
- `backupController` 只提供整库 zip 备份。
- 笔记、复习卡、故事、记忆宫殿、思维导图均无单模块导出端点。

**目标**：支持核心学习资产的单模块导出，便于迁移到移动端（Anki）、分享（PDF/HTML）、归档（Markdown）。

**实现要点**：
1. **笔记导出 Markdown**：`wbNote` 的 cueColumn / noteColumn / summaryColumn 拼装为 Cornell Markdown 模板（`## 线索` / `## 笔记` / `## 总结`），`GET /api/notes/:id/export?format=md` 直接返回 `text/markdown`。
2. **笔记导出 PDF**：复用前端 `src-ui/src/lib/markdown.ts` 的渲染 + 浏览器 `window.print()`，或后端 puppeteer（体积大，谨慎）；优先走前端打印方案。
3. **复习卡导出 Anki apkg**：`wbReviewCard` 的 front / back 映射为 Anki note/card，用 `genanki-js`（纯 JS）或直接写 apkg（本质是 zip + sqlite）。
4. **故事 / 记忆宫殿导出 HTML**：含图片的独立 HTML 文件，便于分享。
5. **思维导图导出**：markmap 已支持 SVG 导出；补 OPML / Freemind `.mm` 格式以便导入其它工具。
6. **批量导出**：笔记列表多选 → 打包 zip（每篇一个 .md）。

**涉及文件**：
- 修改：`src-api/src/controllers/noteController.ts`、`reviewsController.ts`、`storyController.ts`、`mindmapController.ts`
- 修改：`src-api/src/services/noteService.ts` 等（加 `exportAsMarkdown` / `exportAsApkg` 方法）
- 新增依赖：`genanki-js`（或自写 apkg 生成器）
- 修改前端各列表页工具栏：加「导出」按钮

**验收标准**：
- 单篇笔记可导出 .md / PDF，PDF 排版与阅读模式一致。
- 复习卡可导出 .apkg，导入 Anki 后正反面正确。
- 故事导出 HTML 在浏览器打开样式不丢。
- 批量导出生成 zip，文件名含日期。

### F5 · AI 流式输出扩展

**现状证据**：
- 流式端点仅 2 个：`src-api/src/routes/ai-assistant.ts` 的 `POST /chat/completions` 与 `POST /messages/:id/regenerate`（用 `reply.hijack()` + `text/event-stream`）。
- `src-api/src/routes/ai.ts` 的 25 个端点全部一次性 JSON 返回（grep `hijack|sse|stream|reply.raw` 仅匹配错误处理一行）。
- `ai-diagram.ts` 也非流式。

**目标**：把长文本生成类 AI 端点改造为 SSE 流式，降低首字等待，提升交互体验。

**实现要点**：
1. 在 `src-api/src/lib/llm.ts` 暴露 `chatStream(messages, opts)` 生成器（已有 `chatStream` 雏形，需补 JSON 模式流式）。
2. 优先改造的端点（按用户感知排序）：
   - `/api/ai/rag/ask` → RAG 问答（类 ChatGPT 体验）
   - `/api/ai/note/generate` / `/note/extend` → 笔记生成 / 续写
   - `/api/ai/story/draft` / `/capture/draft-note` → 草稿生成
   - `/api/ai/insight/report` → AI 日报文案
   - `/api/ai/review/mnemonics` → 助记口诀
3. 复用 `aiAssistantController.streamSse` 的 hijack 模式，控制器直写 `reply.raw`，绕过统一 JSON 信封（已是项目既定例外）。
4. 前端用 `src-ui/src/api/sse.ts` 的 `EventSource` / `fetch + ReadableStream` 消费，逐字渲染。
5. **保留一次性端点**：评分类（`/recall/score` / `/story/clarity`）、JSON 结构类（`/tags` / `/flashcards`）维持一次性返回，流式无意义。

**涉及文件**：
- 修改：`src-api/src/lib/llm.ts`（`chatStream` 完善）、`src-api/src/controllers/aiController.ts`（流式分支）
- 修改：`src-api/src/routes/ai.ts`（标注流式路由）

**验收标准**：
- RAG 问答首字响应 < 1.5s（取决于 LLM），逐字渲染无卡顿。

### F6 · 主题与外观自定义

**现状证据**：
- `src-ui/src/style.css` 有完整 `--kb-*` 令牌系统，支持浅/深双主题（`:root[data-theme='dark']`）。

3. **紧凑模式**：`<html data-density="compact">`，全局压缩 `--kb-space-*` 与组件高度。
4. 三项设置进 `app-store.ts` 的 `settings.appearance`，持久化并首启应用。

**涉及文件**：
- 修改：`src-ui/src/style.css`（令牌改造）、`src-ui/src/store/app-store.ts`（appearance 字段）
- 新增：`src-ui/src/views/Settings/AppearanceSection.vue`
- 修改：`tailwind.config.js`（primary 色板动态化，若需）

**验收标准**：
- 切换主题色后，全站按钮 / 链接 / 进度条 / 选中态同步变化。
- 字号缩放四档，切换后布局不错乱。
- 紧凑模式下，列表密度提升约 30%，可读性不丢。

## 5. 附录：实施约束与原则

### 5.1 架构红线（沿用现有约定）

1. **Route → Controller → Service 三层边界**：Route 只绑定路径，禁止 `db.` / `axios`；Controller 禁止写 SQL；Service 禁止引用 `FastifyRequest/Reply`。
2. **响应信封**：成功响应由 `index.ts` 的 `onSend` 钩子唯一负责包成 `{ code:200, data }`，Controller 直接 `return` 纯数据；SSE 是唯一例外（控制器直写 `reply.raw`）。
3. **better-sqlite3 同步事务**：`db.transaction((tx) => {...})` 回调**不得写成 async**，否则事务在首个 `await` 处提前提交。
4. **AI Key 隔离**：Key 只在 Node 侧车 / `ai-config.json`（`chmod 600`），永不下发渲染进程。
5. **SM-2 不可被 AI 覆盖**：复习排程是确定性算法，AI 只做「建卡 / 诊断 / 建议」，不改动 `nextReviewTime`。
6. **路由前缀约定**：新模块挂顶层（如 `/sync`、`/tags`），避免被「工作台」`startsWith` 误高亮。

### 5.2 新增表命名与字段口径

- 表名前缀 `wb_`，字段 `snake_case`，时间戳 `TEXT(ISO)`（日历表用 UTC ISO 保证字典序 = 时间序）。
- `user_id` 默认 1（单用户桌面应用），保留以备多用户。
- `tags` 字段统一为逗号分隔串（迁移到统一标签体系前保持兼容）。
- 状态字段用字符串枚举（如 `status: 'inbox'|'today'|...`），不用布尔矩阵。

### 5.3 优先级与排期建议

- **P1（F1–F5）**：建议优先排期，均为桌面效率工具的核心期望，缺失会显著降低使用意愿。
- **P2（F6–F10）**：体验增强，可在 P1 完成后按用户反馈排期。
- **P3（F11–F12）**：锦上添花，F11 成本低可穿插做，F12 需结合产品定位决策。

### 5.4 与既有 P4 候选的关系

本文档已涵盖 README 中提到的 P4 候选方向：
- 「流式输出」→ F5
- 「语义检索进文档库」→ F10
- 「错题讲解（C3）」→ 可作为 F5 / F9 的子项（基于 `wb_review_log` 生成错题解析，归入 AI 流式 + 仪表盘）
- 「多 embedding 批量重建」→ F10 的工程依赖（`embeddings/sync` 分页并发 + 进度回调）
- 「Keychain 加固」→ F1 的安全增强（同步前加密的配套）
